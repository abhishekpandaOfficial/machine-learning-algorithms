🧠 Logistic Regression: theory and mathematics¶

Logistic Regression is a supervised classification algorithm that converts a linear score into a probability. For features $x_1,\ldots,x_p$ and coefficients $\beta_1,\ldots,\beta_p$, the linear score is

$$ z = \beta_0 + \beta_1x_1 + \cdots + \beta_px_p = \beta_0 + \boldsymbol{\beta}^{\mathsf T}\mathbf{x}. $$

The sigmoid (logistic) function maps any real score to $(0,1)$:

$$ \sigma(z) = \frac{1}{1+e^{-z}}. $$

We interpret $\hat p=\sigma(z)$ as the estimated probability of the positive class. A threshold $\tau$ turns probability into a decision: predict positive when $\hat p\ge\tau$ and negative otherwise. The common $\tau=0.5$ is only a default; the correct value depends on error costs, capacity and policy.

The model is linear in the log-odds:

$$ \log\left(\frac{p}{1-p}\right)=z. $$

A one-unit increase in $x_j$ changes the log-odds by $\beta_j$ while other features are held fixed. The odds ratio is $e^{\beta_j}$: values above 1 increase estimated odds, values below 1 decrease them. This is an association, not proof of causation.

Binary cross-entropy loss¶

For labels $y_i\in\{0,1\}$ and predictions $\hat p_i$, training minimises the average negative log-likelihood:

$$ \mathcal{L}(\boldsymbol{\beta})=-\frac{1}{n}\sum_{i=1}^{n}\left[y_i\log(\hat p_i)+(1-y_i)\log(1-\hat p_i)\right]. $$

The loss heavily penalises confident wrong predictions. Regularisation controls coefficient size. L2 regularisation adds $\lambda\sum_j\beta_j^2$; L1 regularisation adds $\lambda\sum_j|\beta_j|$ and can make some coefficients exactly zero.

What to read in evaluation¶

  • Accuracy: overall correctness; can hide minority-class failure.
  • Precision: among flagged positives, the fraction that is truly positive.
  • Recall: among actual positives, the fraction detected.
  • F1: harmonic mean of precision and recall.
  • ROC-AUC: ranking quality across thresholds.
  • PR-AUC: often more revealing when the positive class is rare.

4. Target preparation and leakage review¶

The target in the source is commonly represented as Y/N; this cell validates observed labels instead of silently guessing. We drop the target and obvious identifier fields. This is still an educational baseline, not a production-ready fraud model: inspect all feature definitions and determine whether they were known at the intended prediction time. Fields generated during investigation or after claim adjudication can leak the answer and must be removed before any operational use.

5. Train/test split and preprocessing pipeline¶

The split is stratified so the class proportions are approximately preserved. Numeric columns are median-imputed and scaled; categorical columns are most-frequent-imputed and one-hot encoded. All preprocessing is fit only on the training partition through a single pipeline to reduce leakage.

In [5]:
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, random_state=RANDOM_STATE, stratify=y
)

numeric_features = X_train.select_dtypes(include=np.number).columns.tolist()
categorical_features = [c for c in X_train.columns if c not in numeric_features]

numeric_pipeline = Pipeline(steps=[
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler())
])
categorical_pipeline = Pipeline(steps=[
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("encoder", OneHotEncoder(handle_unknown="ignore"))
])
preprocessor = ColumnTransformer(transformers=[
    ("numeric", numeric_pipeline, numeric_features),
    ("categorical", categorical_pipeline, categorical_features)
])

pipeline = Pipeline(steps=[
    ("preprocessor", preprocessor),
    ("classifier", LogisticRegression(
        max_iter=2000, class_weight="balanced", random_state=RANDOM_STATE
    ))
])
pipeline.fit(X_train, y_train)
print("Pipeline training complete.")

✅ Book-ready summary and checklist¶

Key ideas¶

  • Logistic Regression models a linear relationship in log-odds and returns calibrated-looking probabilities only when the data and calibration procedure support that interpretation.
  • The sigmoid maps a score to a probability; the threshold maps a probability to an action.
  • Cross-entropy rewards accurate probabilities and strongly penalises confident mistakes.
  • Coefficients describe conditional associations. They do not establish causality or fairness.
  • Preprocessing must be fitted on training data only, and the complete pipeline should be saved for serving.

Practical checklist¶

  • Problem, target and intended use are stated.
  • Dataset source and access/licensing notes are documented.
  • Train/validation/test logic and leakage controls are explained.
  • Logistic function, log-odds and cross-entropy formulas are included.
  • Baseline, confusion matrix and threshold-aware metrics are reviewed.
  • Coefficients are interpreted cautiously.
  • Saved artifacts are reloaded with the pinned dependency versions.
  • Validate on a current, approved dataset and monitor drift.
  • Complete privacy, fairness, governance and security review.
  • Add the deployed Streamlit URL: [Streamlit app link — add after deployment].
