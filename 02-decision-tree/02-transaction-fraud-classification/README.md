# Decision Tree: Transaction Fraud Classification

## Goal

Teach Decision Tree classification for transaction-level fraud labels, with particular attention to class imbalance, leakage prevention, and precision-recall trade-offs.

## Dataset strategy

Start with a documented, reproducible synthetic transaction dataset generated by code in this project. Synthetic labels make this a controlled learning exercise; they are not evidence of real-world fraud-detection performance. We will not claim the model can detect real fraud from simulated patterns.

Before adding any externally sourced labelled fraud dataset, verify its provenance, target definition, licence/terms, redistribution rights, and feature leakage risks.

## Planned deliverables

- `notebooks/decision_tree_fraud.ipynb`: theory, synthetic data generation, EDA, training, evaluation and saved outputs.
- `src/`: deterministic dataset generator, training and evaluation code.
- `artifacts/`: fitted pipeline and metadata created by the training workflow.
- `tests/`: data-generation, preprocessing, prediction and artifact-loading tests.
- `app.py`: polished Streamlit demonstration with clear synthetic-data disclaimer.
- `docs/`: reviewed HTML and PDF exports of the executed notebook.
- `requirements.txt` and this README: setup and usage instructions.

## Planned evaluation

Use stratified splitting, a baseline, confusion matrix, precision, recall, F1, PR-AUC and threshold analysis where appropriate. Do not use post-outcome or target-derived fields as predictors. Do not describe the app as a production fraud-control system.
